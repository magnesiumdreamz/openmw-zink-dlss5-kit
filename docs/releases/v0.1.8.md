# v0.1.8 — Updated NR integration and Rafael shader compatibility wizard

This release brings the latest locally tested Feeder/RenoDX combination into the
installer and adds an optional, reversible patcher for Rafael's HBAO and VAIO.
It remains experimental: successful rendering does not mean all GPU stability
issues are resolved.

## Download and start

Download **OpenMW-Zink-DLSS5-Kit-v0.1.8.zip**, extract it, and open its `scripts` folder:

- **Start-OpenMWDLSS5Wizard.cmd** — main kit installer.
- **Start-PostProcessingWizard.cmd** — optional HBAO/VAIO compatibility patcher,
  for users who have separately installed the supported Rafael's Shader Pack 2.1 files.

Close OpenMW and its launcher before installing or patching. Read the README for
prerequisites; the archive does not include Morrowind, OpenMW, or NVIDIA runtime DLLs.
The companion `.sha256` file lets you check the kit archive's integrity.

## Rendering integration and stability-related changes

- Automatic Feeder builds now use **v0.12.1-beta.2**, pinned to commit
  `b4e92bb6c8bfa73c3bfa63decfb083863f48a192`, with the matching hash-checked shader.
- Preserves our Vulkan device-idle wait before imported frame resources are destroyed
  during resize/teardown. The new combination still needs a fresh resize/fullscreen
  regression test; this is not a guarantee against all resolution-change failures.
- Includes upstream Vulkan interop improvements and newer diagnostics.
- Automatically selects or downloads **RenoDX 4.70** (runtime banner v4.7), checking
  both the RHI-hosted archive and extracted add-on hashes. This build adds queue-fenced
  NR resource reuse. NVIDIA DLLs remain separately supplied by the user.
- Rejects mismatched older Feeder shaders. Keeps update backups and build provenance.
- Fixes `-WhatIf` entering the build helper instead of stopping before a build.
- Retains the existing opaque-present safeguard against window transparency, depth
  presets, and launchers that do not continually overwrite settings saved by the game.

## Rafael's HBAO + VAIO patcher and wizard

- Guards HBAO's two blur passes against division by zero.
- Initializes VAIO's light target on an early-return path and guards zero-distance
  lighting/tile calculations.
- Adds an adjustable volumetric-light work limit (default **64**, range 8–256).
  Some glows may be omitted in crowded scenes; normal scene lighting is unchanged.
- Includes the corrected declaration-first VAIO header, avoiding the earlier
  `Line 1 Col 0 unexpected token </>` parser failure.
- Checks original and generated shader contents, refuses unsupported/partially edited
  files, recognizes already-patched files, and supports backed-up restoration.
- Does not automatically enable effects, disable MXAO, or change NR/save/settings files.
  Use HBAO without MXAO if you do not want overlapping AO effects.

The shader patch is optional; it is not automatically applied by the main installer.
Rafael's shader pack is not bundled. Attribution and GPL v3 license text are included.

## Testing and known limitations

- Tested locally on **RTX 3090**, OpenMW 0.51.0, NVIDIA driver 616.56, Mesa/Zink 26.2.0,
  and ReShade 6.8.0. RTX 20/40/50 series were not individually validated here.
- Fresh pinned-source build and isolated file-level installer tests passed, including
  generated provenance, update backups, and mismatched-shader rejection.
- Patcher tests passed in Windows PowerShell 5.1: dry run, expected output hashes,
  repeated application, byte-exact restore, and unknown-version rejection. Wizard
  controls passed a startup smoke test; this was not a full interactive UI test.
- The user confirmed that HBAO and corrected VAIO compile in-game. **Prevention of
  driver hangs by these shader patches has not yet been demonstrated.**
- The short NR-on RenoDX 4.70 run rendered successfully and exited normally, but
  still logged **8 NVIDIA Event 153 errors**. Other runs with postprocessing suffered
  display-driver resets and ReShade submission failures, including without active
  Lossless Scaling. Hook and shutdown-resource warnings remain unresolved.
- The unsuccessful per-frame `sync_home=1` experiment and ineffective cell-cache
  adjustment are not shipped as fixes. No precision conversion or frame generation
  was added.

Start with a fixed **1920x1080** game resolution. Lossless Scaling upscaling/frame
generation can be considered later, but is not a validated stability workaround.
For troubleshooting, keep it off and enable optional effects one at a time.
Keep backups and inspect driver events even when the game appears playable.

See `docs/september-4-update.md`, `docs/postprocessing-compatibility.md`, and
`docs/validation.md` for details and rollback instructions.
